Исследование потоков, процессов и асинхронных методов в Python.

# Цель работы

Изучить различные подходы к параллельному и асинхронному выполнению задач в Python:

- threading
- multiprocessing
- asyncio

---

# Задача 1

Реализовать вычисление суммы чисел с использованием:

- threading
- multiprocessing
- asyncio

## Результаты

| Метод           | Время выполнения |
| --------------- | ---------------- |
| threading       | 0.1470 sec       |
| multiprocessing | 0.2591 sec       |
| async           | 0.1237 sec       |

## Вывод

Для вычислительных задач multiprocessing обычно эффективнее, так как использует несколько процессов и позволяет обходить ограничение GIL.

Threading менее эффективен для CPU-bound задач.

Asyncio не предназначен для тяжёлых вычислений, но может показывать хорошие результаты на небольших задачах.

# Задача 2

Реализовать парсинг веб-страниц с использованием:

- threading
- multiprocessing
- asyncio

Результаты сохранялись в PostgreSQL через SQLModel.
В асинхронной версии использовалось асинхронное подключение к PostgreSQL через asyncpg и AsyncSession.
Каждая программа содержала функцию `parse_and_save(url)`, которая:

- загружала HTML-страницу;
- извлекала заголовок страницы (`title`);
- сохраняла данные в PostgreSQL;
- выводила результат на экран.

## Использованные технологии

- requests
- aiohttp
- BeautifulSoup
- SQLModel
- PostgreSQL

Для хранения результатов парсинга была добавлена таблица `ParsedPage`, содержащая URL страницы и её заголовок. Это связано с тем, что таблицы из первой лабораторной работы относятся к финансовому приложению и не подходят для хранения данных веб-страниц.

## Результаты

| Метод           | Время выполнения |
| --------------- | ---------------- |
| threading       | 1.9333 sec       |
| multiprocessing | 3.6950 sec       |
| async           | 0.8589 sec       |

## Вывод

Для I/O-bound задач наиболее эффективным оказался asyncio.

В асинхронной реализации использовались:

- aiohttp для HTTP-запросов
- asyncpg и AsyncSession для асинхронной работы с PostgreSQL

Это позволило получить наилучшее время выполнения среди всех подходов.
